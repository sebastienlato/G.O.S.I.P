## Batched setup steps — only the selected items

1. **Cloudflare account + external trigger (Phase 21, conditional on decision 1).** Use [Cloudflare sign-up](https://dash.cloudflare.com/sign-up); verify email, enable MFA, use Workers **Free**, add no domain/card/subscription. The same account can issue the Radar token below. A paid-plan/card prompt is a stop, not a setup step.
   - GitHub → Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate. Name `GOSIP external dispatch`, resource owner `sebastienlato`, select **only** `G.O.S.I.P`, repository **Actions: Read and write**, no Contents write or administration. Set a finite expiry (90 days recommended), record its renewal date privately. [Dispatch permission reference](https://docs.github.com/en/rest/actions/workflows#create-a-workflow-dispatch-event). This permission is repository-wide Actions control, not a single-workflow permission; accept that scope explicitly.
   - Do **not** create a dummy running trigger now. Phase 21 must first produce reviewed/tested trigger code and duplicate-run guards. Then, in one setup visit: Workers & Pages → Create Worker `gosip-publish-trigger` → paste that reviewed code → Settings → Variables and Secrets → encrypted secret `GITHUB_DISPATCH_TOKEN` with the PAT. Disable public `workers.dev`/preview routes and add no HTTP route, KV, R2, D1 or analytics service. No Cloudflare management API token is needed for this owner dashboard path.
   - Add one Cron Trigger, every 15 minutes UTC, using the exact expression supplied by Phase 21 after collision/deduplication checks. The fixed destination is `https://api.github.com/repos/sebastienlato/G.O.S.I.P/actions/workflows/publish-live.yml/dispatches`, POST body `{"ref":"main"}`; GitHub bearer auth, API accept/version headers and GOSIP User-Agent belong in reviewed server code. Never put the PAT in a URL or an Actions/browser variable. An Actions secret alone cannot be read by the outside scheduler.
   - Return only Worker name, token-expiry date and “configured”; Phase 21 verifies actual externally triggered build/deploy/cleanup and repeated publication intervals. Token rotation at expiry is a recurring owner responsibility; no claim this can be provisioned forever in one action. If access/setup is pending, Phase 21 still ships truthful freshness UI with the existing scheduler.

No separate paid account/API plan.
