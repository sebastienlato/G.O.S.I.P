# Architecture — Phase 4

A static React + TypeScript application. `App.tsx` owns selected-event context separately from the detail dialog and explicit map-focus requests. One filtered array drives map/feed; NWS renders one co-located marker for the selected or earliest period while the feed exposes all periods. `src/state/explorer.ts` validates/serializes source, search, layers, window, view and map preference; `useExplorerFilters.ts` synchronizes history. No data/selection/camera are encoded in links.

`src/data/events.ts` uses an `is_demo` discriminated union, extended with `kind: forecast` and `kind: thermal` for environment data. The demo parser still accepts only labeled simulations, preserving its 18 fixtures and fixed clock. Earthquakes retain provider IDs/network/code, validated source links, nullable estimates/review/update, occurrence, retrieval and feed-generation times. `filterEvents` accepts an explicit reference clock; the app supplies current device time at minute resolution for USGS and the fixed snapshot for demo.

`src/data/usgs.ts` exposes one fixed endpoint and a bounded parser/provider. Streaming enforces 2 MB, the envelope allows at most 2,000 records, and a 12-second abort covers fetch/body reading. Bad records are counted; invalid envelopes/all-invalid observations fail. Non-earthquake records are explicitly excluded. One in-flight request is shared; attempts are throttled for 60 seconds with rate-limit backoff. No polling. `earthquakeCache.ts` stores one versioned compact parameter envelope in localStorage, at most 2 MB and 2,000 source records. It reuses `parseUSGS` to regenerate trusted display fields; any rejected/excluded cached record invalidates the whole copy. Retrieval/generation and rejection/exclusion counts are preserved. Expiry is 24 hours from the older source timestamp, enforced on read and active USGS ticks; inactive/closed pages cannot run cleanup. `earthquakeStore.ts` holds snapshot/error in memory, exposed to React through `useSyncExternalStore`. `useEarthquakes.ts` ticks UI time/expiry only. Initial source selection restores cache before considering a request. Source switches do not refetch an already loaded snapshot. Failed refreshes preserve data with a stale warning; successful refresh replaces the snapshot, including corrections/removals. No historical correction ledger. A separate small versioned cadence record persists retry time and last refresh error; clearing the snapshot deliberately preserves it. Web Locks with `ifAvailable` exclude simultaneous same-origin requests without queueing retries. Storage events revalidate and adopt newer saved snapshots (including empty responses), cooldowns and errors. Without locks, storage coordination is best effort; denied/full storage degrades visibly to in-memory operation. Manual refresh is blocked while offline/hidden. There is no reconnect or visibility-triggered fetch. Different origins, profiles and devices are not coordinated.

`FeedSource.tsx` owns the visible source choice/status, provenance, limits and manual refresh/fallback controls. Fixtures and real observations never share an array or automatic fallback. Detail dialogs use conditional provenance and measurement fields, with focus return. Marker labels/badges reflect their data source. Source choice defaults to demo to preserve offline startup; explicit `source=usgs` links restore or request observations. Cached labels and original timestamps remain visible while stale, refreshing or failed. Clear-cache removes only the saved copy; successful refresh writes a new one.

`WorldMap.tsx` still loads MapLibre JS/CSS/worker only in interactive mode, uses local Natural Earth geometry, handles resize/lifecycle cleanup and WebGL/network fallback to SVG, preserves selection, and supports explicit regional focus and cooperative touch gestures. List/static entry avoids all interactive-map downloads. No clustering; the full feed remains the way to inspect overlapping markers. Mobile feed scrolls with the page.

Vite builds `dist/`; Vitest tests parser/provider/filter/URL boundaries; Playwright tests deterministic production desktop/mobile behavior and injected failures. No credentials, auth, backend, external tiles/fonts, analytics, deployment or service worker. Only selected USGS/NWS views make external data requests. Review independently scoped source permissions in `DATA_POLICY.md`. Snapshot persistence does not cache application assets or establish offline cold-start support.

## Environment path

`weather.ts` resolves the fixed Lower Manhattan point through NWS `/points`, validates the discovered HTTPS `/gridpoints/{office}/{x},{y}/forecast` URL, then fetches that forecast. Each response is limited to 100,000 streamed bytes; one 12-second abort covers both requests and body reading. Maximum 32 periods, bounded strings, calendar/interval validation, explicit units and nullable values; duplicate/bad periods are counted and all-invalid input fails. Source URLs/icons in forecast content are not fetched or rendered as links. Text is rendered by React without HTML.

`useWeather.ts` retains one snapshot in memory across source switches; the independent provider deduplicates in-flight loads and spaces all attempts by one hour (including failures), respecting longer exposed Retry-After. No persisted weather snapshot or cadence record, Web Locks or cross-tab coordination. Initial selection attempts once; offline/hidden attempts become a manual retry. UI ticks update freshness and forward-looking windows, never fetch. Failed refresh retains data as stale; success replaces it, including empty responses. Stale after six hours from the oldest update/generation/retrieval time. Device clock accuracy matters; expired periods leave the view at minute resolution. An hourly attempt limit is not a promise of hourly NWS updates.

`fire.ts` adds four original synthetic thermal examples through the existing demo validator plus sensor-field checks. They are separate from the original 18 demo fixtures and from real sources, use the same fixed demo clock, and carry invented confidence/radiative-power/brightness values. No FIRMS requests or credentials.

URL sources now include `nws` and `fire-demo`. Both expose Environment only. Discrete source changes retain window/view, clear search/layers/selection, and never substitute sources automatically. Forecast intervals intersect `[now, now + window)` and sort ascending; other sources retain backward windows and descending time. Forecast cards/details distinguish validity from update/retrieval; thermal details distinguish synthetic values from measured evidence. The one forecast map marker avoids stacking all periods on the same coordinate. Direct list/static entry still bypasses MapLibre downloads.
