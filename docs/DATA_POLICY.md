# Data policy

For each real feed before public integration, briefly record: official provider, exact allowed use/redistribution, attribution, limits, refresh interval, coverage and sensitivity. If unresolved, use fixtures or another provider; do not stop unrelated development.

Normalized event: id, category, title, summary, coordinates/region optional, source_name/source_url optional, occurred_at/published_at optional, collected_at, status, freshness, is_demo, coverage_note optional. Preserve provider identifiers and corrections. Distinguish sensor observations from verified incidents and media reports from confirmed events. Never imply complete worldwide coverage. Treat third-party content as untrusted. Protect privacy and avoid unnecessary tactical precision for sensitive conflict data.

## Phase 0 assets

- Events: 18 original GOSIP synthetic fixtures; no real incident claims or external source links. Scenario occurrence/publication and fixture snapshot timestamps are distinguished. Broad markers carry no measured precision or confidence.
- Geography: Natural Earth 4.1.0, 1:110m, packaged by world-atlas 2.0.2. [Official terms](https://www.naturalearthdata.com/about/terms-of-use/) reviewed 2026-10-08 permit public-domain use, modification, and electronic dissemination. Bundled files and package notice are in `public/`; no remote service/quota. Historical generalized borders are illustrative.
- Runtime validation rejects unknown categories, unlabeled/non-demo records, invalid coordinates, malformed timestamps/order, duplicate IDs, and missing/oversized strings. React renders event text without raw HTML. A future feed adapter must validate its own broader contract and safe source URLs; the demo parser deliberately accepts only simulations.

## Phase 2 — USGS earthquake observations (reviewed 2026-10-08)

- **Provider/endpoint:** U.S. Geological Survey / ANSS; [M2.5+ past-week GeoJSON](https://earthquake.usgs.gov/earthquakes/feed/v1.0/summary/2.5_week.geojson), documented by the [official feed format](https://earthquake.usgs.gov/earthquakes/feed/v1.0/geojson.php). This endpoint is designed for application use. Only numeric source parameters, place text, IDs, status, times and event links are used; no photographs, logos, impact products or third-party narrative reports are copied.
- **Use/redistribution basis:** [USGS copyrights/credits](https://www.usgs.gov/information-policies-and-instructions/copyrights-and-credits) places USGS-produced data in the U.S. public domain, with exceptions for marked third-party material. The [scientific-data release policy](https://www.usgs.gov/faqs/what-usgs-policy-release-scientific-data-are-any-usgs-products-restricted?items_per_page=6&page=1) describes public scientific data as available at no cost. The source-specific [ANSS Data and Products Policy](https://www.usgs.gov/media/files/anss-data-and-products-policy), sections 1, 3 and 4, makes participant data available for education and other appropriate purposes, requires attribution for distributed data/metadata, and identifies ComCat as the source-parameter catalog. Together these support this attributed public educational display of the published summary data. This is a scope-specific decision, not blanket permission for every USGS-hosted third-party asset or feed. No USGS endorsement is implied.
- **Attribution:** source panel and details credit “U.S. Geological Survey / ANSS”; provider ID, network and code are retained, with a validated HTTPS link to the individual USGS event page. The source policy link above supplies original terms. No account, billing mechanism or payment method is involved.
- **Cadence/quotas:** feed documentation says updated every minute. [USGS rate-limit guidance](https://geohazards.usgs.gov/pipermail/realtime-feeds/2022-January/000028.html) documents 60-second caching and HTTP 429; no numeric request allowance or SLA is specified there. GOSIP restores a valid local snapshot on first USGS selection, otherwise requests once while online/visible and outside cooldown; later refresh is manual. It shares in-flight requests and enforces a minimum 60-second attempt interval. HTTP 429 backs off at least 5 minutes; an exposed longer Retry-After is honoured. No polling, auto-retry, paid alternative or quota upgrade. Phase 3 persists cooldown/last failure across reloads and same-origin tabs, with Web Locks for exclusive requests and storage events for saved-result updates. No delayed requests queue behind a lock. With missing locks, tab coordination is best effort; with denied/full storage, only the page-local cooldown is reliable. These are local safeguards, not a global quota guarantee.
- **Bounds/failure:** 12-second total request timeout, maximum 2,000,000 streamed bytes and 2,000 input features; oversized/invalid envelopes fail rather than truncate. Bad records and duplicates are rejected with visible counts; non-earthquake types are excluded with counts. An all-invalid response fails. Empty valid responses remain distinct from failures. Any previous snapshot is retained but marked stale after a failed refresh. Synthetic fallback requires an explicit switch and keeps SIMULATED labels.
- **Validation/semantics:** finite bounded coordinates, magnitude/depth and integer timestamps; five-minute future clock tolerance; update cannot precede occurrence. Strings and IDs are bounded; source URLs allow only credential-free HTTPS `earthquake.usgs.gov/earthquakes/eventpage/<id>` with no query/fragment. React renders text, never feed HTML. Missing optional measurements/review/update stay null. Magnitude is earthquake size, not shaking intensity or impact; depth is a provider estimate in km and may be negative. Review status is preserved as supplied, including a withdrawal label if `deleted` appears. Each successful snapshot replaces the previous one, so vanished records disappear; this does not establish why they disappeared. No historical correction ledger is claimed.
- **Time/coverage:** occurrence, provider update, feed generation and retrieval are distinct. USGS uses current device time at minute resolution; fixtures keep the fixed demo clock. Staleness is a local UI rule: more than 15 minutes since the older of feed generation/retrieval, or any refresh failure. M2.5+ week coverage is incomplete geographically and temporally; small events are omitted and reporting may be delayed (USGS notes many non-U.S. events arrive 15+ minutes after origin). An empty result is never proof of no earthquakes. Summary uncertainty values are not available; none are invented. Place text is retained without inferred country/geocoding.
- **Sensitivity/privacy:** only publicly released estimated earthquake epicentres; no vulnerable-person, station, response-team, or tactical conflict positions. No personal reports/impact counts are ingested. Direct browser requests disclose ordinary connection information to USGS; no cookies/credentials/referrer are sent by the adapter. Bundled map remains independent of USGS.
- **Verification:** a one-off endpoint check returned HTTP 200 with `Access-Control-Allow-Origin: *`. Automated tests use original invented transport fixtures under `tests/fixtures/`; these are never bundled as real observations. Availability and free access at review time are not guarantees at scale. Disable/throttle/cache the layer if service conditions change; spending remains prohibited.

## Phase 3 — local persistence and cadence (reviewed 2026-10-08)

- Same endpoint and source-specific permission scope as Phase 2; no new products or services. Current [official GeoJSON documentation](https://earthquake.usgs.gov/earthquakes/feed/v1.0/geojson.php) still states one-minute updates. The previously reviewed rate-limit archive returned HTTP 503 during this recheck; retain the conservative 60-second attempt minimum, at least five-minute 429 backoff and longer exposed Retry-After. No numeric allowance, unlimited traffic or SLA is inferred.
- One compact versioned localStorage snapshot, maximum 2,000,000 UTF-8 bytes and 2,000 total accepted/rejected/excluded input records. Revalidation regenerates derived text and source links through the provider parser. Corruption, incompatible versions, future retrieval beyond tolerance, or age of 24 hours from the older generation/retrieval timestamp rejects the entire cache. Cleanup happens on next cache access or active USGS tick; browser storage can outlive a closed page until it is opened again. In-memory data can remain visible after cache expiry with stale/time labels.
- Cache restoration never updates generation/retrieval time and never counts as a provider refresh. Failed refreshes preserve data and persist failure status separately; successful responses replace current and saved data, including corrections/removals and empty feeds. Cache is per browser profile/origin, may be evicted or modified locally, and is not a historical archive or proof of authenticity.
- Clear-cache deletes the saved snapshot, keeps current in-memory observations and cooldown, and allows the next successful manual refresh to save again. Storage failure is visible; no fallback service or paid resource is activated. No service worker or tested offline cold-start asset path; only an already loaded app's offline use is tested. Demo arrays/clocks and fixtures remain separate and are never stored as observations.

## Phase 4 — NWS New York forecast (reviewed 2026-10-08)

- **Scope and rights:** NOAA / National Weather Service point metadata and textual/numeric land forecast for Lower Manhattan only. The [NWS API documentation](https://www.weather.gov/documentation/services-web-api) explicitly describes the API as open data, free for any purpose and without service fees. The [NWS disclaimer](https://www.weather.gov/disclaimer), “Use of NOAA/NWS Data and Products,” allows public-domain information to be used without charge, except marked material, with no ownership or endorsement claims and no altered content presented as official. GOSIP reproduces forecast text/values under its own UI labels and credits NOAA / National Weather Service in the panel/details. No copyright is claimed over NWS material. No logos, imagery, third-party content or official warning product are copied. This is an independent source decision, not an extension of USGS permission.
- **Endpoints:** fixed [point lookup](https://api.weather.gov/points/40.7128,-74.0060) followed by its validated `https://api.weather.gov/gridpoints/{office}/{x},{y}/forecast` link. The current lookup returned `OKX/33,42`; resolving on each eligible attempt accommodates changed grid mappings. A one-off check returned HTTP 200 and `Access-Control-Allow-Origin: *` on point/forecast responses. Browser requests use the browser's User-Agent (the API requires a User-Agent); no key/account is currently required. If access rules change, disable/fail visibly rather than create an account or paid substitute. Links use the fixed [NWS location page](https://forecast.weather.gov/MapClick.php?lat=40.7128&lon=-74.0060).
- **Quota/cadence:** NWS documents unpublished reasonable rate limits, not unlimited access or an SLA. Forecast update cadence varies; display provider `updateTime` and `generatedAt`, not an invented fixed publication schedule. API docs describe roughly 12-hour periods over seven days on approximately 2.5 km grids. GOSIP allows one initial eligible load and later manual attempts at least one hour apart per page; no polling or auto-reconnect retry. Both point and forecast requests share a 12-second timeout; 100,000 streamed bytes each and 32 periods maximum. HTTP failures including 429 retain the one-hour delay, extended by a longer exposed Retry-After. That header was not listed in the observed CORS exposed headers, so the conservative fallback matters. Browser HTTP caching may also apply. Limits reset on reload and are not coordinated across tabs/devices; broader public scale requires another zero-cost rate-control decision or disabling the layer, never billing.
- **Semantics/coverage:** one requested grid location, not global weather, citywide conditions or an instrument position. Temperature includes its supplied °F/°C unit and period-value context; wind retains provider text/units, precipitation is probability in percent, not amount. Null stays “Not supplied.” No numerical forecast temperature uncertainty is invented. `occurred_at` is the forecast period start internally and is labeled **Forecast valid from** in the UI; validity end, source update, generation and retrieval remain distinct. Filters intersect the next selected interval, ordered soonest first. Forecasts are predictions, not measured observations, official alerts or verified impacts. No alerts are loaded; users can follow NWS links for current warnings. One marker represents the selected or earliest period, not a hazard extent.
- **Failure/privacy:** no weather data is saved to localStorage. A bounded memory snapshot survives source switching and failed refresh; successful responses replace it including empty responses. Stale after six hours from the oldest update/generation/retrieval or on refresh failure; elapsed validity removes periods from results. Malformed envelopes, unsafe discovered URLs, impossible dates/intervals, invalid units and out-of-bounds values are rejected; invalid periods are counted, all-invalid data fails. React displays plain text. No arbitrary icons, URLs or remote maps load. Direct requests disclose ordinary connection details including IP to NWS; credentials/referrer are omitted. Tests use invented payloads, not live availability.

## Phase 4 — fire exploration remains synthetic

The [FIRMS area API](https://firms.modaps.eosdis.nasa.gov/api/area/) requires a free MAP_KEY requested with an email; its stated allowance is 5,000 transactions per ten minutes, with larger queries costing multiple transactions. The API lists sensor-specific availability, including US/Canada-only Landsat NRT. No key or account was created, and no FIRMS data was downloaded or redistributed. The general citation page could not be retrieved in this review; no blanket redistribution approval is inferred. A future integration must confirm the selected product's citation/terms, cadence, geographic coverage and credential handling separately.

Four original GOSIP examples instead illustrate VIIRS-like thermal semantics. NASA's [official fire-data caveats](https://forum.earthdata.nasa.gov/viewtopic.php?t=5188) explain non-vegetation heat sources, missed detections/cloud gaps and why points do not establish burned area. The [VIIRS 375 m user guide](https://www.earthdata.nasa.gov/s3fs-public/2024-07/VIIRS_C2_AF-375m_User_Guide_1.0.pdf) documents brightness temperature in kelvin and radiative power in megawatts. Our broad coordinates, times, values and confidence labels are **invented**, not NASA records or satellite pixels. They imply neither wildfire perimeters, impacts nor probability of wildfire. The original 18 demos remain unchanged. No sensitive-person or tactical real-time positions are introduced.

## Phase 5 — global report source review (2026-10-08)

No live news feed was enabled. Neither existing USGS nor NWS permission extends to reports.

- **ReliefWeb / OCHA:** [official API documentation](https://apidoc.reliefweb.int/) and [appname requirements](https://apidoc.reliefweb.int/parameters) say access has no fees, but a pre-approved application name is required from 1 November 2025. None was requested or borrowed. Documented limits are 1,000 entries per call and 1,000 calls per day, not an unlimited traffic allowance. Its continuously updated humanitarian archive is curated, not complete global news; no fixed report publication cadence or accuracy guarantee is promised. Contributed reports can remain copyrighted by their original sources. API access does not authorize blanket article redistribution; original publisher rights and attribution would need checking for the chosen product. Credentials/approval and rights remain unresolved, so no report API calls, content copies or live integration.
- **Wikinews:** [current copyright policy](https://en.wikinews.org/wiki/Wikinews:Copyright) assigns post-16 December 2024 material CC BY 4.0, older post-25 September 2005 material CC BY 2.5, and earlier material public domain; credit and license would need preserving for selected text, with other assets checked separately. The old reuse page is superseded. [Official closure notice](https://en.wikinews.org/wiki/MediaWiki:Sitenotice) and [Wikimedia's May bulletin](https://diff.wikimedia.org/2026/05/12/wikimedia-foundation-bulletin-2026-issue-9/) confirm all editions became read-only on 4 May 2026. It is an archive, not a current news source. No archival integration, API quota assumption, content ingestion or account was introduced.

**Shipped alternative:** six GOSIP-authored fictional reports, separate `reports-demo` source and fixed 8 October 2026 16:00 UTC clock. All publisher names, claims and source timestamps are invented. Source links resolve only to bundled original plain-text fixtures; they do not impersonate external publishers. No third-party article text/images, accounts, billing, remote data requests, report cache, polling, geocoding or translation service. $0 local operation; no claim of unlimited free hosting at scale. Future live feeds still require an independent review and fail-closed limits.

**Semantics and sensitivity:** publication drives backward windows; occurrence is nullable and never inferred from publication or update. Scenario retrieval and publisher update remain separate. Four source languages, one separately credited fixture-author translation, other translations absent. All text renders as React text, not HTML. A single corrected-date example supplies one prior title/summary/time and correction note; it neither establishes comprehensive history nor independent verification. Publisher repetition is not corroboration. Four deliberately broad regional markers; one unknown and one safety-withheld location have no coordinates, marker or map navigation. No precise vulnerable-person or tactical positions. Missing coverage never establishes absence of events. Parser rejects unsafe links/IDs, oversized/control text, invalid language/calendar/order, duplicate IDs, non-demo labels and overly precise/out-of-range coordinates.


## Phase 6 — digital-world source review (2026-10-08)

**Decision: original simulations only.** No measurement API was called, third-party dataset downloaded or redistributed, or account/key/billing provisioned. Official documentation was reviewed; existing USGS/NWS approvals do not extend to digital feeds.

| IODA / Georgia Tech Internet Intelligence Lab | The [official API reference](https://api.ioda.inetintel.cc.gatech.edu/v2/) lists entity, signal, outage-event and summary endpoints; the [official resource hub announcement](https://ioda.inetintel.cc.gatech.edu/reports/ioda-launches-new-user-resource-hub-2/) points to signal guides. Public documentation alone did not establish a source/product-specific redistribution license, required attribution wording, numeric quota, credential policy, free-service guarantee or cadence. **Methods, cadence and coverage:** OONI's [interpretation guide](https://ooni.org/support/interpreting-ooni-data/) describes near-real-time publication dependent on volunteers' countries, networks, tests, targets and timing. Anomalies can be false positives; country coverage and repeat-test counts do not measure a population or independent corroboration. Its API is recommended for light queries, with bulk access a separate path; no bulk service is used here. IODA's [original official research proposal](https://www-old.caida.org/funding/ioda/dals-satc_proposal.xml) describes BGP route visibility, active probing and network telescope signals for macroscopic disruptions. These measure different parts of connectivity and cannot alone identify causes or affected users. Current per-signal cadence, coverage and third-party rights would need confirmation before any IODA adapter. No universal update frequency is invented.

**Sensitivity:** OONI's [data policy](https://ooni.org/about/data-policy/) notes that stored measurements may contain identifying information, including IPs/HTTP headers, and publishes collected measurement data. Public availability does not make raw redistribution appropriate here. GOSIP includes no raw contributor record, probe IP, tested URL, precise probe position or linked raw measurement. Reference links go only to fixed official educational pages, are labeled as methods rather than fixture provenance, and send no referrer when opened.

**Shipped content:** six GOSIP-authored digital scenarios; all numeric values, times, country/network contexts and claims are invented. No OONI/IODA data, logo or affiliation is asserted. Three reachability scenarios (drop, missing interval, near-baseline sample) and three web-comparison scenarios (anomaly, missing denominator, no anomaly in sample). Responsive block medians include a prior-day baseline interval; test anomalies include a denominator when supplied. Missing samples/denominators/updates/networks are null rather than fabricated zeroes. Anomaly, no-anomaly, no-samples and inconclusive states never become confirmed incidents or intentional censorship. No confidence percentage, affected-person estimate, cause or actor is supplied.

**Bounds and operation:** maximum 50 schema-validated records, bounded strings/IDs/counts, known method/result enums, ordered intervals/baselines and fictional private-use ASNs only. Rejects unknown fields, including arbitrary URLs and probe data. Four broad five-degree illustrative markers, two explicitly unknown/withheld locations; no map action for null positions. Half-open intervals overlap the backward fixture window and sort by interval end; original fixture clock is 8 October 2026 16:00 UTC. No digital request, automatic refresh, cache, error substitution or stale-live-data claim exists. This is $0 local development with free/account-free core access, not a promise of unlimited hosting. Any future live path must independently bound requests/payloads/cadence, honor Retry-After and fail closed when rights or quotas fail; no paid fallback.
